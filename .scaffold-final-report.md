## Combined open questions / known-rough across all phases

### Cross-phase issues

1. **API path drift between PRD/frontend/backend.** PRD says `/api/me`, backend mounts at `/api/auth/me`. Frontend was patched to match the backend. Pick one canonical form before adding any other clients.
2. **Drizzle migrations schema location.** drizzle-kit 0.28 stores bookkeeping in the `drizzle` schema, not `public`. Backend startup probe now accepts either. If you swap to a different Drizzle version, re-validate this.
3. **`hello.mp4` is a 24-byte stub.** Phase 1 noted no ffmpeg. Phase 3 created a minimal ftyp atom so `<video>` triggers `onError` once instead of 404. Drop a real ~3-second silent .mp4 before user testing.
4. **Postgres port** moved to 5433 (5432 was in use). All references parameterized via `DATABASE_URL` / `POSTGRES_PORT`. Free up 5432 if you want the PRD-default port.

### Inherited from Phase 1

- shadcn 4.x CLI rewrites `globals.css` aggressively. Phase 2B avoided the CLI; Phase 3 didn't touch it. Don't run `npx shadcn add` without expecting to re-paste brand tokens.
- shadcn's stock `Button` has compact defaults (h-8, px-2.5). Phase 2B used `size="lg"` in product-critical buttons. Worth a brand-pass review.

### Inherited from Phase 2A

- `SESSION_SECRET` env var is unused (cookie value is the raw UUID). Keep it in `.env.example` for the real-auth migration.
- `practice_session` table is deferred. If analytics or session-level features need it, add a migration.
- `rep_source` enum has `'dev'` but no UI dispatches it. Forward-compat for a "dev: instant pass" button.
- Hard-fail vs. soft-warn on DB unreachable: currently soft-warn (server boots; `/api/health` reports `dbReachable: false`). Switch to hard-fail if you'd rather see the failure loudly.
- Streak rollover doesn't auto-consume freezes. Add freeze-consumption logic before launch.

### Inherited from Phase 2B

- `TooltipProvider` is wrapped at the top of `App.tsx`. If new providers come in, mind the wrap order.
- Dashboard fell back to `mastered=38, total=75` when offline; with the Phase 3 fix it falls back to `touched=38`.
- First-sign tutorial auto-routes after 1.2s. Routes-smoke spec tolerates this (asserts placeholder synchronously after `goto`).
- PWA service worker is disabled in dev. Switch on in `vite.config.ts`'s `devOptions.enabled` if you need SW testing locally.

### New from Phase 3

- Dev panel (`position: fixed; bottom-left`) overlaps the self-report row on default viewports. Spec 3 uses `force: true` as a workaround. Move the dev panel below the fold or make it collapsible.
- The mastery bar label "X / 75 signs in progress" reads stilted. Marketing copy pass before launch.
- `tests/unit/seed.spec.ts` uses **pure** generator functions — it doesn't talk to the DB. A separate DB-backed integration spec could be added if seed I/O regressions become a concern; the e2e specs implicitly cover it.

```bash

docker compose up -d
```

### 2. Common moves

| Want to… | Command |
|---|---|
| Run all tests | `DATABASE_URL=... npm test` |
| Run unit only | `npm run test:unit` |
| Run a single Playwright spec | `npx playwright test frontend/tests/e2e/<file>.spec.ts` |
| Open a Playwright trace | `npx playwright show-trace test-results/<dir>/trace.zip` |
| Reset the DB and reseed | `docker compose down -v && docker compose up -d && npm run db:migrate && npm run db:seed` |
| Watch Vitest | `cd frontend && npm run test:watch` |
| Browse the DB | http://localhost:8088 (Adminer; server=`postgres`, user=`asl`, password=`asl_dev_only`, db=`asl_pilot`) |
