# SuperBuilders Partner Projects — Portfolio Teardown

## Identity disambiguation

"SuperBuilders" is, in this context, **Superbuilders EdTech** — an Austin, TX engineering dev shop. Confirmed via three independent signals:

1. Their own marketing copy (`superbuilders.dev`, pulled from the JS bundle): *"Hi, we are the Superbuilders. We are the AI Engineer Dev Shop building the best edtech in the world for Alpha School, GT School, Texas Sports Academy, Montessorium, and more. Our Mission: to accelerate educational outcomes for 1 billion kids."*
2. Their primary domain `superbuilders.school` describes itself as *"a foundry for transformative education companies, staffed by trailblazing innovators from the first cohort of GauntletAI."*
3. Their LinkedIn handle is `superbuilders-edtech`, headquarters Austin, TX, and they share a building with GauntletAI HQ (416 N Congress Ave, Austin, per the Luma event listing).

Not to be confused with: Super Builders construction in San Jose, Supreme Builders Group ATX, Maxx Builders Austin, jacekbilski/superbuilders (a Java library), or "Build Superagency." The Gauntlet/SuperBuilders relationship is: Superbuilders is staffed by Gauntlet AI graduates (Cohort 1, Cohort 2), and is the dev shop that builds the actual production software for Alpha School's TimeBack platform.

## Project-level aesthetic detail

### Alpha Dash + Alpha Academics (`dash.alpha.school`, `academics.alpha.school`)
- **Stack:** Next.js (pages router) + Emotion CSS-in-JS + MUI + Montserrat. Light-mode only.
- **Palette:** White background, ink text `#212B36`, accent `#40B8D4` (a friendly cyan/teal — also the theme-color in meta), snackbar surface `#161C24`, muted greys `#637381`, `#919EAB`.
- **Components:** Heavy MUI smell — `MuiBox-root`, `SnackbarItem`, soft shadows (`0 8px 16px 0 rgba(145,158,171,.16)`), 8px border-radius, snackbar bottom-toast pattern. Top progress bar (`nprogress`) in `#40B8D4`.

- **Quality bar:** Polished, production. Live for student use 2025-26 school year.

## Patterns across projects

1. **Stack convergence is real but not absolute.** Next.js (pages or app router) shows up for anything customer-facing or app-shell (Alpha Dash, Academics, Content Engine, Montessorium). Vite + React is used for high-performance marketing sites and embedded apps (TSA, Khan-TimeBack, SuperBuilders' own internal projects). **Webflow** is used when a non-engineering team needs to own copy (GT Anywhere).
2. **Tailwind is the default.** Where it's not Tailwind (Alpha Dash uses Emotion + MUI), the team chose CSS-in-JS deliberately for the older Next.js pages-router stack. Newer projects all smell Tailwind/shadcn.
3. **Custom display fonts + Inter body** is the convention. `IntegralCF-Heavy` (TSA), `Serifa` (Montessorium), `Inconsolata` (GT), `Geist` (Content Engine), `Montserrat` (Alpha Dash). They never lean on system fonts — every project picks one personality font.
4. **No shared SuperBuilders branding template on partner sites.** Each partner brand stands alone — there is no "Powered by SuperBuilders" footer credit, no shared nav, no shared color system. Projects are allowed to deviate freely by partner brand.
5. **Engineering-grade performance discipline.** TSA's HTML alone has font-display tuning, LCP preloads, CLS prevention comments, lazy-loaded GTM, Microsoft Clarity. This is a team that ships with Core Web Vitals in mind.
6. **Internal tooling is openly Tailwind + shadcn/Geist** (Content Engine, projects-tau). They don't bother with custom display fonts for internal apps — Geist or system sans is fine.
7. **AWS Cognito for auth on TimeBack-family apps; Firebase for cohort internal tools; Google SSO for staff tools.** They pick the right auth per audience.
8. **PWA + manifest on practice apps** (Khan-TimeBack, TSA). They expect students to install to home screen.

## Closest analogue to our ASL app

**Khan-TimeBack (`khan-timeback.com`)** is the closest structural analogue, hands down. Why:
- It is a **browser-based learning app for students** doing **isolated practice sessions** with **progress tracking** — exact same shape as our ASL pilot.
- The bundle reveals primitives we will need: `Exercise Session`, `ExerciseSessionState`, `AssignmentRow`, `Completed`, `Celebrating progress`, `Developing`, "Be specific about concerns and open to solutions" (rubric-style feedback strings). This is *practice + scored attempt + state machine + feedback*, which maps 1:1 to our `prompt → camera attempt → pass/fail → hint → retry → save progress` flow.
- Stack: **Vite + React + AWS Cognito + PWA**. Vite + React is the lighter, faster choice for a single-purpose practice app — exactly what we want.
- Tailwind + custom font is the family convention.

Secondary analogue: **Alpha Dash** (`dash.alpha.school`) for the progress/dashboard surface around the practice loop. If we want our "saved progress over time" view (Requirement 12) to feel native to SuperBuilders, mimic the Alpha Dash app shell — Montserrat, light-mode-only, soft shadows, cyan accent, rounded-8 cards.

## What the pattern tells us to do (or avoid)

1. **Do: Use Vite + React + Tailwind for the practice app, Next.js only if we need SSR for marketing.** Khan-TimeBack and TSA both prove Vite is the SuperBuilders default for non-marketing apps. Avoid CRA, avoid Remix, avoid SvelteKit — none of those appear anywhere in the partner portfolio.
2. **Do: Pick one personality font + Inter for body.** Their family convention is one strong display font per project. For an ASL learning app, `Inter` for body is safe, and a friendly, generous display font (something in the spirit of Geist, DM Serif Display, or Montserrat) for headlines fits the "education, but modern" palette. Do not ship with default system sans.
3. **Do: Tailwind + shadcn/ui smell for the app surface.** Alpha Content Engine is the in-family reference — rounded-2xl, soft shadows, zinc or slate neutrals, dark-mode-aware. This is the lowest-risk visual choice that signals "engineer-built but production-quality."
4. **Do: PWA manifest + favicon family.** Every shipped practice/student app has one. Cheap, signals polish.
5. **Do: Color accent in the cyan/teal family or a deliberate purple.** Alpha Dash uses `#40B8D4`, SuperBuilders' own favicon is `purple_dot.svg`. Avoid the generic Tailwind blue-500 — pick something with a slight tilt.
6. **Avoid: Webflow, v0.dev raw output, or anything that screams "no-code."** Webflow is reserved for partner marketing sites only. v0.dev was used at Montessorium but is the outlier; for an engineer-deliverable our work should look hand-built.
7. **Avoid: Material UI for new builds.** Alpha Dash's MUI smell is from a legacy stack. Newer SuperBuilders work is Tailwind/Geist/shadcn. Match the newer convention.
8. **Avoid: Heavy marketing-page chrome on the practice surface.** Their practice app (Khan-TimeBack) is a focused app-shell, not a landing page with a hero. We should have a small marketing landing for first-time visitors, then a clean app shell for logged-in practice.

The brief PDF itself (`superbuilders-partner-project-asl-learning-with-computer-vision.pdf`) uses **numbered requirements with blue/navy section headers and thin horizontal rules** — same documentation aesthetic. Our README and submission docs should mirror that: numbered requirements, terse "must / must not" prose, an explicit "Out of Scope" list, and a "Success Criteria" checklist.
